# Tool — the `dast` orchestrator

The scanner and pipeline for the thesis *"DAST in CI/CD Pipelines — A Case Study
on Security Evaluation."* It combines OWASP ZAP (DAST) with an AI
triage/verification layer and emits a SARIF 2.1.0 report plus a human summary.
One console script, `dast`, drives every stage. It runs locally in Docker on
arm64; every image is pinned arm64-native.

**The documentation is in [`docs/`](docs/)** — this README is the operational
quickstart, the docs are the reference:

- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — the vocabulary, how the pieces
  fit, and why the pipeline is shaped the way it is. **Start here.**
- [`docs/OUTCOMES.md`](docs/OUTCOMES.md) — every status a finding can carry, per
  stage, and what it resolves to.
- [`docs/TARGETS.md`](docs/TARGETS.md) — how a target is defined: every
  `target.yml` field and what it changes.
- [`docs/COMMANDS.md`](docs/COMMANDS.md) and [`docs/api/`](docs/api/) — every
  command, flag and module (generated by `dast commands` / `dast docs`).

All commands below run from this `Tool/` directory; `../Targets/` is the sibling
targets directory the tool scans.

## Prerequisites

- Docker Desktop (arm64), configured **not** to suspend the VM on idle — an
  `--oob` run needs out-of-band callbacks to keep arriving throughout a scan.
- [`uv`](https://docs.astral.sh/uv/).

## Quickstart — one scan end to end

```bash
# 0. one-time: shared network, config, secrets, and the target's source for Noir
docker network create dast-net
cp config/scanner/default.env config/scanner/.env            # then set SCAN_ZAP_API_KEY
cp config/scanner/secrets.env.example config/scanner/secrets.env  # then add SHARED_OPENROUTER_API_KEY
git clone --depth 1 --branch v1.16.0 \
  https://github.com/go-gitea/gitea ../Targets/gitea/src

# 1. bring up the persistent target, then seed its users/fixtures (idempotent)
docker compose -f ../Targets/persistent.yml up -d
../Targets/gitea/env/seed-users.sh
../Targets/gitea/env/seed-repo.sh

# 2. bring up the ephemeral ZAP scan job
docker compose -f docker/ephemeral.yml --env-file config/scanner/.env up -d

# 3. install deps and drive the chain (from the host)
uv sync
uv run dast scan gitea         # Noir → seed ZAP → spider → passive → bounded active scan
uv run dast triage latest      # the two arms (deterministic control + LLM); --no-llm for the free arm
uv run dast verify latest      # one bounded loop per finding, over stdio MCP tool wrappers
uv run dast report latest      # SARIF 2.1.0 + Markdown summary, merging the three readings

# 4. tear down the ephemeral job when done
docker compose -f docker/ephemeral.yml down
```

Everything after Noir goes through the ZAP REST API — there are no
baseline/full-scan wrapper scripts. Each run's artifacts land together in
`data/runs/<run-id>/` (`<run-id> = <timestamp>-<target>-<config-digest>`); the
cross-run `data/run-index.jsonl` tracks cost and runtime.

## Common variations

```bash
uv run dast gitea                       # the whole chain in one command
uv run dast scan gitea --auth admin     # authenticated scan (the biggest detection lever)
uv run dast scan gitea --oracle         # ceiling mode: also seed the documented CVE sinks
uv run dast triage latest --out-suffix qwen --screening-model qwen/qwen-plus-2025-07-28  # model A/B

# out-of-band confirmation (e.g. Cacti's blind RCE): bring up the OOB sink first
docker compose -f docker/oob.yml up -d
uv run dast verify latest --oob

# standalone SAST + SCA static-analysis findings (no key, not a pipeline stage)
uv run dast static-analysis gitea

uv run dast harness                     # a sheet of runs, unattended, into one comparison table
uv run dast run-index                   # every recorded run: runtime + cost, one table
uv run dast commands && uv run dast docs # regenerate docs/COMMANDS.md and docs/api/ from the code
```

## Layout

| path | what |
|---|---|
| `src/dast_orchestrator/` | the orchestrator — seven layered packages (foundation / domain / context / adapters / analysis / stages / cli); see [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). |
| `src/dast_harness/` | the harness — drives a sheet of runs into one comparison table (`dast harness`). |
| `mcp/` | thin stdio MCP wrappers for nuclei / sqlmap / ffuf / the browser probe, plus the read-only `context_server.py`. |
| `docker/` | the tool's container assets: `ephemeral.yml` (the ZAP scan job), `oob.yml` (interactsh + split-horizon resolver), `dns/`, `ctags/`. |
| `config/` | `scanner/` (env + secrets), `harness/` (task sheets), `excerpts/` (HTTP-exchange policies). |
| `prompts/` | every system prompt, versioned by filename (`<group>/<pass>.v<N>.md`). |
| `schemas/` | the artifact contracts (`triage-result`, `verification-result`, `run-metrics`, `noir-ai-context`). |
| `data/` | run outputs (gitignored): `data/runs/<run-id>/`, `data/harness/<sheet>/`, `data/run-index.jsonl`. |
| `docs/` | the documentation (above). |
| `tests/` | hermetic unit + integration tests (no live containers or API calls); an opt-in `e2e` tier. |

## Deployment — three stacks on `dast-net`

Three compose stacks with **independent lifecycles**, kept separate on purpose —
that separation is the core of the CI/CD-compatibility argument: the persistent
**targets** (`../Targets/persistent.yml`), the ephemeral **scan job**
(`docker/ephemeral.yml`), and the tool's persistent **OOB sink**
(`docker/oob.yml`, only for `--oob`). They talk over the shared external Docker
network `dast-net`, so ZAP reaches a target by container name, never `localhost`.

The scan job holds only the ZAP daemon. `dast` and its stdio MCP wrappers run on the
host and start everything else as single-use `docker run --rm` containers: Noir and
Ctags off `dast-net` over a read-only mount of the source clone, curl and the
verification tools on it.

## Pinned images

All native arm64, never `:latest`: `zaproxy/zap-stable:2.17.0`,
`ghcr.io/owasp-noir/noir:1.2.1` (1.x tags carry no leading `v`),
`projectdiscovery/nuclei:v3.4.10`, `secsi/sqlmap:1.10`, `secsi/ffuf:2.2.1`,
`projectdiscovery/interactsh-server:v1.2.4`, `semgrep/semgrep:1.140.0` (with a
commit-pinned `semgrep-rules` checkout), and `ghcr.io/google/osv-scanner:v2.0.2`.
The targets' own images are pinned in `../Targets/` (see
[`docs/TARGETS.md`](docs/TARGETS.md)).

## Tests

```bash
uv run pytest          # hermetic unit + integration
uv run pytest -m e2e   # the live tier — needs Docker and the running stacks
```

Dependency manager is **uv**; the package is `src/dast_orchestrator` (src layout),
exposing one console script, `dast`.
